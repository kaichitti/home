# SH-01J 電池持ち診断・修正ツール(FOMA 停波対策)

docomo の 3G(FOMA)停波後、AQUOS ケータイ SH-01J の電池持ちが悪くなった原因を調べて修正するツールです。

## なぜ電池が減るのか

SH-01J は出荷時、ネットワーク設定が「LTE / 3G 自動」になっています。

- 停波前は、LTE が弱い場所(屋内・地下・郊外)で **3G に切り替えて** 通信していた
- 停波後は 3G の電波が無いのに、端末は **3G を探し続ける**(電波サーチ)
- 電波サーチは待受中に最も電池を使う処理なので、電池持ちが目に見えて悪化する

また **VoLTE が OFF** だと、停波後は通話ができず、着信・発信のたびに無い 3G へ切り替えようとします。

## このツールでやること

| コマンド | 内容 |
|---|---|
| `diagnose` | ネットワーク設定、VoLTE、電波サーチ時間、圏外時間、3G 利用時間、ウェイクロック、電池の状態を調べる(端末は変更しない) |
| `fix` | 確認しながら次を適用:ネットワークを **LTE のみ** に/**VoLTE ON**/常時 Wi-Fi スキャン OFF。元の値は `sh01j_backup.json` に保存 |
| `restore` | `fix` 前の設定に戻す |
| `reset-stats` | 電池統計をリセット(修正後の効果測定用) |

## 使い方

### 1. 準備(最初の1回だけ)

1. PC に [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)(adb)と Python 3 を入れる
2. SH-01J で開発者向けオプションを出す:`設定` → `端末情報` → `ビルド番号` を 7 回押す
   (メニュー名は機種のバージョンで少し違うことがあります)
3. `開発者向けオプション` → `USB デバッグ` を ON
4. USB ケーブルで PC とつなぎ、端末に出る「USB デバッグを許可しますか?」で OK
   (Windows で認識しない場合は、シャープの SH-01J 用 USB ドライバを入れてください)

### 2. 診断と修正

```sh
python3 sh01j_battery.py diagnose    # 原因を確認
python3 sh01j_battery.py fix         # 修正(1項目ずつ確認が出ます)→ 最後に再起動
python3 sh01j_battery.py diagnose    # 再起動後、「LTE のみです」になっているか確認
```

### 3. 効果の確認

```sh
python3 sh01j_battery.py reset-stats
```

満充電 → USB を抜く → 1〜2 日普段どおり使う → もう一度 `diagnose`。
「電波サーチ時間」と「圏外の時間」が減っていれば改善しています。

終わったら USB デバッグは OFF に戻して構いません。

## PC が無い場合(手動での対処)

1. **VoLTE を ON**:`設定` の通話/ネットワーク関連のメニューで「VoLTE」を ON
2. **ネットワークを LTE のみに**:`設定` → モバイルネットワーク →「優先ネットワークタイプ」(表示があれば)を LTE に
   メニューに無い場合、ダイヤルで `*#*#4636#*#*` を入力して「携帯電話情報」画面が出れば、そこで「LTE only」を選べます(出ない機種もあります)
3. **電波の弱い場所**(寝室、職場の奥など)に長時間置くときは **機内モード** にするのが最も効果的

## それでも改善しないとき

- **電波環境**:停波前に 3G でつながっていた場所は、今は LTE 圏外/弱電界のことが多いです。`diagnose` の「圏外の時間」が多い場合、端末側では直せません(docomo に電波改善を申し込めます)
- **電池の劣化**:SH-01J は 2016 年発売です。数年使っていれば電池パックの劣化も大きいので、ドコモショップ等で電池パック交換を検討してください
- **乗り換え**:停波で SH-01J の通話は VoLTE のみになっています。電池・電波の問題が続く場合は、4G/5G 対応の新しいケータイへの機種変更も選択肢です

## 注意

- `fix` は Android の設定値を書き換えます。`restore` でいつでも戻せます
- 機種やソフトのバージョンによって、設定値の名前が異なり読み取れないことがあります。その場合は「読み取れませんでした」と表示されるので、手動で確認してください
- 実機の代わりに偽の adb を使ったテストで動作確認しています:`python3 -m unittest discover -s tests`
