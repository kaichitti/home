## デバッグ・不具合修正（2026-10-28）

実際にサーバー（PHP 8.3 + MariaDB 10.5）で動かし、全画面・全操作（164項目）を自動テストして見つかった不具合の修正。
修正後は全項目が合格し、ブラウザ（Chromium）でもJavaScriptエラーは出ていない。

### 動作を止めていたもの
- **初回セットアップが進めない** — 配布ZIPに `storage/uploads/` が含まれず、setup.php の環境チェックが必ず NG になり
  「次へ」が表示されなかった。無ければ作成する（外部から読めないよう .htaccess も置く）。
  Step 4 で指定したアップロード先も、無ければ作成し書き込みできるか確認する（以前は後で添付が必ず失敗していた）。

### 機能・データの不具合
- **台帳の取引種別に不正な値を送ると登録失敗／空の種別で保存** — 許可値（買取・交換・委託販売受け・その他）の検証を追加。
- **POS会計で消費税設定の変更を検知できない場合があった** — 「ちょうど」で預かった会計では、画面との合計不一致より先に
  「お預り金額が足りません」と判定され、本来の「ページを再読み込みしてください」の案内が出なかった。判定順を修正。
- **レジ精算で全角カンマ・全角円記号を含む金額がエラー** — 画面の計算は通るのに保存時だけ拒否されていた。
- **アラートの確認が二重に記録される** — 確認済み・他テナントのアラートIDでも成功扱いになり、監査ログに記録されていた。
- **会員の項目に「0」と入力すると空になる** — 住所・備考などの「0」が NULL として保存され、詳細画面でも表示されなかった。
- **配列を送ると文字列「Array」として保存** — 古物区分名・販売記録・会員検索・管理者ログイン名で発生。
- **台帳更新の入力エラー時、対象が無いと新規登録フォームになる** — 「保存」で別の台帳が登録され得たため 404 にした。
- **台帳登録時の会員同時登録で番号重複が起きると 500 エラー** — 台帳は登録済みのため案内メッセージを表示する。

### 使い勝手
- **ログイン失敗時にテナントコード・メールアドレスが消える** — 入力値を残すようにした。
- **拠点の登録・編集で入力エラー時に拠点名・住所が消える** — 入力値を残すようにした。
- **監査ログのページ送りで絞り込み条件が外れる**・**未知の操作種別が二重エスケープ表示** — 修正。

- **check.php** — `storage/uploads` 固定ではなく、`config/.env` の `UPLOAD_DIR` の書き込み可否を表示する。

### セキュリティ
- **72バイトを超えるパスワードを受け付けていた**（テナント利用者・システム管理者のパスワード変更）。
  bcrypt は72バイトより後ろを無視するため、末尾が違うパスワードでもログインできた。72バイト以内に制限。
- **migrate.php の実行に CSRF トークンが無かった** — セッションのトークンを照合するようにした
  （Cookie の SameSite=Lax により多くのブラウザでは実害は出にくかったが、多層防御として追加）。

### 入力値の扱い（PHP版と Python版に同じ入力を数千通り送って比べた結果、2026-10-29）
- **会員の住所・職業・電話番号、台帳の登録者・更新者名、販売記録の会員番号、ダッシュボードの登録者名が「0」のとき「-」と表示されていた**
  — 空欄のときだけ「-」を表示する（以前の修正で保存は直っていたが、詳細画面の表示が残っていた）。
- **取引の取消理由・レジ精算の備考に配列を送ると「Array」と保存される** — 配列は空欄として扱う。
- **台帳の CSV/PDF 出力で絞り込み条件に配列を送ると Warning が出て、監査ログにも配列が残る** — 文字列以外は条件なしとして扱う。
- **POSの在庫検索の exact・レシート呼出やレシート表示の format・doc・w などに配列を送ると Warning（Array to string conversion）、
  添付ファイルの type も同様** — 文字列以外は未指定として扱う。

## 致命的（実運用を止めていたもの）

1. **管理メニューが表示されない**
   レイアウトが参照する `$userRole` `$userName` `$alertCount` 等を
   どのコントローラーも渡しておらず、管理者でもサイドバーに
   ユーザー管理／拠点管理／アラート／監査ログ／CSV出力が一切出なかった。
   → BaseController::render で共通変数（csrf_token / isAdmin /
   currentUserId 含む）を全ビューへ自動注入。

2. **入力値の二重エスケープでデータ破損**
   Request が入力を htmlspecialchars してDB保存 → ビューで再エスケープされ、
   「&」を含む品名が `&amp;` として表示・CSV/PDF出力されていた
   （DB内も汚染）。
   → 入力時のHTMLエンコードを廃止し、出力時エスケープに一本化。
   既存データ修復用に `database/fix_double_encoding.sql` を追加。
   エクスポート時は旧データも自動で平文に戻す。

3. **台帳削除・ユーザー無効化・拠点削除が常に403**
   各画面のフォームが参照する `$csrf_token` が未注入で空になっていた。
   → 1. の共通注入で解消。あわせてCSRFトークンを「ページ表示ごとに
   再生成」から「セッション内で再利用」に変更（複数タブで開くと
   先のタブが必ず403になる問題も同時に解消）。

4. **添付ファイルのダウンロード不整合**
   詳細画面のリンクは「台帳ID + 種別」を渡すのに、コントローラーは
   IDを ledger_files.id と解釈（IDズレで404や別ファイル取得の恐れ）。
   さらに買取受付表はビューの `receipt_form` とDB enum の
   `purchase_receipt` が不一致で、リンク自体が永久に表示されなかった。
   → 台帳ID+種別で解決するよう修正（旧形式のファイルID直指定も互換維持）。
   日本語ファイル名がDL時に「___.png」になる問題も RFC 5987 で修正。

5. **XREA分離構成でそもそも起動不可能**
   DEPLOY.md は「BASE_PATH を修正」と指示するが、エントリポイントに
   BASE_PATH の仕組みが存在せず、public/ の中身を public_html/ へ
   コピーすると src/ を発見できなかった。
   → public/index.php・public/admin/index.php 両方に BASE_PATH 定義を
   実装し、DEPLOY.md を実装と一致する手順に更新。setup.php / check.php
   にも分離構成用の SETUP_BASE / BASE_PATH 上書きを追加。

6. **セッションタイムアウト直後のログインが403**
   タイムアウトで session_destroy された後、CSRFトークンが
   セッションに保存されず、次のログイン送信が必ず失敗していた。
   → トークン生成・検証時にセッションの再開を保証。

    ページネーションを整備。監査ログ・台帳・会員は実装済み、今回

## セキュリティ強化・不具合修正（2026-10）

脆弱性解析の結果にもとづく修正。DBスキーマ変更は不要（既存データ・既存の
暗号化ファイルはそのまま利用可能）。ローカルに PHP 8.3 + MariaDB 環境を構築し、
全修正をマルチエージェントで敵対的に再レビューのうえ検証済み。

### セキュリティ

S1. **運用スクリプトの無認証アクセスを遮断** — `setup.php`・`migrate.php`・
    `check.php` は認証もCSRFも無く、消し忘れると第三者がDB再初期化・
    暗号鍵の再生成（＝既存の暗号化データが復号不能になる）・スキーマ変更・
    環境情報の閲覧を行えた。
    - `setup.php`: `config/.env` が既に存在する（セットアップ済み）場合は
      インストーラを完全にロックし、再初期化・鍵再生成を防止。
    - `migrate.php`: 実行にシステム管理者ログイン（`/admin/`）を必須化。
    - `check.php`: 稼働中（`config/.env` 存在時）は管理者ログインを必須化し
      診断情報の漏えいを防止。未設定時のみパス確認用に素通し。
    ※ これらは従来どおり**使用後は必ず削除**してください。
S2. **CSV数式インジェクション対策** — エクスポートCSVの各セルで、先頭が
    `= + - @`（およびタブ・CR）の値にシングルクオートを前置して無害化
    （`ExportController::csvSafe`）。品名・相手方氏名等に数式を仕込まれても
    ExcelでマクロやHYPERLINKが発火しない。PDF出力には影響しない。
S3. **認証付き暗号（AES-256-GCM）へ移行** — 本人確認書類の暗号化を
    認証なしの AES-256-CBC から AES-256-GCM（認証タグ付き）に変更し改ざんを
    検知可能に。鍵の導出方法は不変で、**旧CBCで保存済みのデータも引き続き
    復号可能**（後方互換）。
S4. **会員照会APIの個人情報露出を抑制** — `member.lookup` の応答から
    本人確認書類番号を除去し、登録の有無（真偽値）のみ返却。台帳フォームの
    引用でも番号は自動入力しない。承認判定はサーバー側で会員を参照する実装の
    ため影響なし。
S5. **ログイン後のアカウント状態を毎リクエスト再評価** — 無効化・削除・
    ロール変更をセッションへ即時反映（従来は最大15分、タイムアウトまで権限が
    残存）。DBアクセスはリクエストあたり1回に限定。
S6. **IPアドレス偽装対策** — 監査ログ等のIP取得は既定で `REMOTE_ADDR` のみを
    信頼。`X-Forwarded-For` は信頼できるプロキシ配下で `TRUST_PROXY=true` を
    設定した場合のみ参照する。
S7. **Cookie Secure 判定の統一** — 全エントリポイントで
    `!empty($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off'` に統一
    （`isset()` では HTTPS=off でも Secure が付与される不整合を解消）。
S8. **セキュリティヘッダー追加** — `.htaccess` に Content-Security-Policy を
    追加（インライン利用のため script/style は 'unsafe-inline' を許可しつつ
    外部スクリプト・プラグイン・フレーム埋め込み・フォーム送信先を制限）。
    HTTPS運用時は HSTS のコメントを解除。

B3. **商品画像の拡張子** — アップロード保存時の許可拡張子に `gif`・`webp` を

## セキュリティ強化・不具合修正 第2弾（2026-10）

第1弾で残していた項目と、追加調査で判明した不具合への対応。検証環境（PHP 8.3 + MariaDB）での
動作テストに加え、変更全体を独立した複数のレビューで検証し、レビューで見つかった問題
（並行リクエストによる制限超過、表記ゆれによる制限回避、在庫ロックのデッドロック、
編集時の無効ユーザー再有効化 等）も本リリースで修正している。

### セキュリティ

S9. **ログイン試行制限（総当たり・アカウントロックDoS対策）** — 新設の
    `LoginThrottle` で試行履歴（`login_attempts`）を記録し、
    (a) 同一IPから15分間に30回失敗でそのIPを一時拒否、
    (b) 同一IPから同一アカウントへ30分間に5回失敗でその組合せを拒否。
    アカウント単位のロック（5回失敗で30分）は、**過去にそのアカウントで
    ログイン成功したIP（信頼済みIP・30日間）からの試行には適用しない**。これにより
    第三者が故意に失敗を重ねて正規ユーザーを締め出す攻撃を防ぎつつ、未知のIPからの
    総当たりは引き続き遮断する。信頼済みIPからログインしてもロックは解除しない
    （解除すると攻撃者に試行回数を再付与するため）。
    - 照合の**前**に試行を記録（予約）してから件数を数えるため、同時に大量の
      リクエストを送っても上限を超えて照合できない（アカウントロック側も1文の
      UPDATE で判定と加算を原子的に行う）。
    - アカウントは入力文字列ではなく**DB上のユーザーID**で識別する。DBの照合順序は
      大文字小文字・全角・アクセント・ゼロ幅文字などの表記ゆれを同一視するため、
      入力文字列で数えると表記を変えるだけで制限を回避できてしまう。
    - IPv6 は /64 単位で数える。識別子は SHA-256 で保存し、メールアドレスは平文で残さない。
    - 制限で拒否する場合もダミー照合を行い、応答時間からアカウントの有無を推測されない
      ようにする。ロック中のため照合せずに拒否した試行は、アカウント単位・組合せ単位の
      制限には数えない（ロック中の再試行でロックや制限の期間が延び続けることはない）。
      組合せ単位の制限で拒否した試行も同様。いずれもIP単位の制限には数え、IP単位の判定を
      通過した試行はアカウントの有無・状態に関係なく同じだけ枠を消費する（存在推測の防止）。
S10. **ロックが4回目の失敗で掛かっていた不具合** — MySQL の UPDATE は SET 句を
    左から順に評価するため、加算後の値で判定しており実際は4回目でロックされていた。
    仕様どおり5回目でロックするよう修正。
S11. **システム管理者ログインに試行制限を追加** — 従来は無制限に総当たりできた。
    テナント側と同じ IP単位・組合せ単位・アカウント単位（信頼済みIPは除外）の制限を
    適用。ユーザー名は半角英数字と . _ - のみ受け付け、管理者IDで識別する。
S12. **初期パスワード（Admin7777）の利用を禁止** —
    (a) システム管理者: 初期パスワードは DEPLOY.md・setup.php に公開されているのに、
        変更を強制する仕組みも変更画面も無かった。初期パスワードでログインすると
        変更画面（新設・12文字以上）以外の管理画面・migrate.php・check.php を
        使えないようにし、ナビに「パスワード変更」を追加。変更は監査ログに記録。
    (b) テナント利用者: 初期パスワードへの再設定と、現在と同じパスワードへの変更を禁止。
        旧バージョンで初期パスワードに戻していた利用者も、次回ログイン時に変更を強制する。
S13. **ユーザー列挙対策** — 存在しないアカウントへのログインでもダミー照合を行い、
    応答時間の差からアカウントの有無を推測しにくくした。ダミーのコストはPHPの既定
    （8.3まで10、8.4以降12）に合わせ、実アカウントもログイン成功時に既定コストへ
    再ハッシュする（初期データのアカウントは初回ログインまではコスト12のまま）。
    再ハッシュは、照合中に別の操作でパスワードが変更されていない場合に限り行う。
S14. **会員照会・POS在庫検索のレート制限** — セッション単位で会員照会は1分30回、
    在庫検索は1分120回まで（超過時は429）。スクリプトによる連続照会の速度を落とす
    ベストエフォートの抑止策（再ログインでリセットされる。会員一覧など職員に閲覧が
    認められた画面は対象外）。
S15. **オーナー・ユーザー管理の保護** —
    (a) ユーザー編集への直接POST（is_active=0 / role=user）でオーナーや自分自身を
        無効化・降格できた → 拒否。
    (b) オーナーのメールアドレス（ログインID）は、他の管理者からは変更できないようにした
        （本人が「アカウント設定」から現在のパスワード確認付きで変更する）。
    (c) 初期データ（schema.sql）と管理画面から作成したテナントでオーナー／主拠点フラグが
        立っておらず、保護が機能していなかった → 設定するよう修正し、既存環境は
        migrate.php で補正（各テナントの有効な管理者を優先してオーナーに設定し、有効な
        管理者がいない場合は最初の管理者を設定。オーナー列が無い旧バージョンからの移行時も
        同様で、一般ユーザーはオーナーにしない）。
    (d) 所属拠点に他テナントの拠点IDを指定できた → 自テナントの拠点のみ許可。
S16. **拠点ログインコードのテナント間衝突** — 一意性がテナント内のみで、ログイン時は
    全テナント横断で検索していたため、他社と同じコードを登録すると混線した。
    新規登録・変更時は全テナント横断かつテナントコードとも重複不可。既存の重複コードは
    曖昧としてログインに使えない（任意のテナントへ誘導しない）。重複は migrate.php に
    一覧表示されるので、該当テナントでコードを変更すること（コード以外の項目の編集や
    テナントの再開は、重複が残っていても可能）。
S17. **setup.php の強化** — 完了画面（初回ログイン情報）は「その場でセットアップを
    完了したセッション」に限り30分間だけ表示可（他は従来どおり全面ロック）。
    アプリURLは http(s) の正しいURLのみ受け付け、`.env` へ書き込む値の改行・制御文字を
    除去して設定行の注入を防止。完了後はDBパスワード等をセッションから消去。
S18. **X-XSS-Protection を "0" に** — CSP 導入に伴い OWASP 推奨値へ変更。
S19. **プロキシ配下でのIP取得を偽装されにくく** — `TRUST_PROXY=true` のとき、
    X-Forwarded-For の左端（クライアントが自由に書ける）ではなく、自前のプロキシが
    追記した右端から解決する。`TRUSTED_PROXIES`（IP/CIDR）を設定すると、そのプロキシ
    経由の通信に限って転送ヘッダを信頼する。偽装が容易な Client-IP ヘッダは参照しない。
    `TRUSTED_PROXIES` の行末の注釈（# …）は取り除き、解釈できない値（「10.0.0.1/」の
    ような不正なプレフィックス長を含む）は全アドレス一致とはせず無視してエラーログに
    記録する（1件も解釈できない場合は転送ヘッダを信頼しない）。IPv4射影アドレス
    （::ffff:a.b.c.d）は IPv4 として照合する。

B4. **DBのタイムゾーン不一致** — DB接続のタイムゾーンを未設定だったため、DBサーバーが

B6. **在庫の超過販売** — 同じ商品を複数行に分けると在庫チェックをすり抜けて販売できた

    数量・取引金額・年齢の範囲を保存前に検証し、エラーとして案内する（従来は列の上限を
    超えるとDBエラーになっていた）。
B7. **承認フローの判定漏れ** — 本人確認書類のアップロードに失敗しても「書類あり」と
    みなされ承認待ちにならなかった。実際に保存できたかで判定するよう修正。
    あわせて、ファイル保存失敗の通知で承認待ちの警告が上書きされ消える問題も修正。
B8. **フラッシュメッセージの表示崩れ** — 「&#9888;」「&#10003;」が文字のまま表示されて
    いたのを修正（⚠ ✓ を直接記述）。
B9. **移行途中環境での販売登録エラー** — sales テーブルに member_code 列が無い環境でも
    自動で列を補ってから登録する（会計処理はトランザクション開始前に補修）。
B10. **不正なURLパラメータで500エラー** — `?page[]=x` 等で型エラーになっていたのを404に。
     パスワード変更やテナント作成（初期パスワード）でNUL文字を含む値を送ると、
     500エラーや原因不明のエラーになる問題も修正。
B11. **setup.php 完了画面のリンク先** — アプリURLを保存しておらず常に「/」になっていた。
B12. **台帳フォームの入力内容が消える** — 入力エラーで画面を再表示すると、取引年月日・

     戻っていた。入力した値を表示するよう修正（編集時の登録済み商品画像の件数表示も維持）。

### レシート印刷とプリンタ未接続時の流れ（ご要望の仕様）

P1. **会計確定時にプリンタの接続を確認** — 「会計を確定する」を押すと、この端末に設定した
    レシートプリンタの接続状態を確認する。
    - **接続あり**: 確認ダイアログ →「決済を確定する」で **決済完了 → レシートを印刷**。
    - **接続なし**: 「⚠ レシートプリンタが接続されていません」ダイアログ（理由・合計・お預り・
      お釣りを表示）。**「許可して決済する」を押した場合のみ決済完了 → レシートを画面に発行**
      （そのまま提示可能。後から取引履歴で印刷・再発行できる）。「キャンセル」なら決済せず
      カートもそのまま残る。会計記録には「未印刷（画面発行）」として残る。
    - 印刷に失敗した場合は「決済は完了しています」と明示し、画面にレシートを表示して再印刷できる。
P2. **プリンタの接続方式（端末ごとに設定・「POS設定・プリンタ」画面）**
    - プリンタなし / ブラウザ印刷（OSにインストールしたプリンタ）/ USB直結（WebUSB・ESC/POS）/
      シリアル・Bluetooth（Web Serial・ESC/POS）。用紙幅 58mm / 80mm。
    - USB・シリアル直結では接続状態を自動検出し、日本語を画像（ラスター）で印字、自動カット、
      現金会計時のキャッシュドロワー開放に対応。テスト印刷・ドロワー開放テストあり。
    - ブラウザ印刷はブラウザから接続状態を確認できない仕組みのため「接続あり」として扱う
      （画面上部のバッジにも「ブラウザ印刷」と表示）。
    - POS画面右上に接続状態バッジ（接続中／未接続）を常時表示し、抜き差しを自動で反映。

### 追加した機能

P3. **会計（取引）単位の管理とレシート番号** — 会計ごとに `pos_transactions` を作成し、
    レシート番号（YYYYMMDD-連番・テナント内で日ごとに採番）、担当者、拠点、会員番号、
    明細スナップショットを保存。以前は明細ごとの販売記録しかなく、会計の単位・レシートが無かった。
P4. **単価 × 数量・単品値引・小計値引（円 / %）** — 以前は「明細の合計金額」を手入力する方式で、
    数量を変えても金額が変わらなかった。
P5. **消費税（内税 / 外税・税率・端数処理）とインボイス対応** — 店舗設定で税率（0〜30%）・
    内税／外税・切り捨て／四捨五入／切り上げを指定。レシートには適格簡易請求書の記載事項
    （登録番号、税率ごとの対象額と消費税額）を印字。
P6. **支払方法と預り金・お釣り** — 現金 / クレジット / 電子マネー / QR / その他。
    現金はお預り入力（ちょうど・+1,000 等のボタン）とお釣り計算、不足時は確定不可。
    キャッシュレスは承認番号等を記録可能。
P7. **レシート・領収書の発行と再発行** — レシートの再印刷時は「【再発行】」と印字。
    領収書は宛名・但し書きを指定して発行（現金かつ税抜5万円以上は収入印紙欄を付記）。
    再発行・領収書の発行は監査ログに記録（不正防止）。
P8. **取引履歴・取引詳細・CSV出力** — 期間・状態・支払方法・拠点・レシート番号・会員番号・
    品名で検索。明細単位の売上CSV（管理者・数式インジェクション対策済み）。
P9. **取引の取消（返品）** — 管理者が理由を入力して取消。販売記録を削除して在庫を戻し、
    会計とレシートは「取消」として保存（取消レシートも印刷可）。返金方法を案内。
P10. **レジ精算（日計）** — 日付・拠点ごとに件数・点数・売上・値引・消費税・支払方法別・
    時間帯別・取消を集計。釣銭準備金と金種別枚数（1万円〜1円）から現金実査額を計算し、
    理論現金残高との過不足を表示・記録・印刷。前日以前の会計をこの日に取り消して現金返金した
    分は理論残高から差し引く。精算は履歴として残る。
P11. **バーコードスキャナ対応** — 検索欄で Enter（スキャナの読取完了）を押すと、シリアル番号の
    完全一致または台帳番号（123 / #123 / L123）で1件に決まれば即カートに追加。
P12. **会員番号の照会表示**（会員名を表示）、**保留・呼出**（最大10件）、**カートの自動保存**
    （再読み込み・セッション切れでも消えない）。
P13. **二重送信・改ざん防止** — 会計ごとの送信キーで、通信エラー後の再送でも二重に登録されない
    （「同じ会計を再送信」ボタン）。金額はサーバーで再計算し、画面の合計と一致しない場合は確定しない
    （税設定の変更等を検出）。同時に複数端末で最後の1点を会計しても1件だけ成立する。
P14. **POS設定（管理者）** — 店舗名・住所・電話・登録番号・税設定・レシート上下メッセージ・
    領収書の但し書きの既定値。サイドバーに「POS」セクション（POSレジ／取引履歴／レジ精算／
    POS設定・プリンタ）を新設。

     型エラーは「リクエストの形式が正しくありません」（400）として扱う。ログイン画面・台帳一覧・アラート一覧
     などで配列パラメータを送ると500エラーになっていた箇所も個別に修正。
B35. **会員の登録で長い入力がDBエラーになっていた** — 氏名・住所・電話番号等の文字数上限を検証していな
     かった（拠点の所在地も同様）。入力段階でエラーとして案内し、会員フォームにはエラーの一覧を表示する。
     同時登録などで会員番号が重複した場合も500エラーにせず案内する。
B36. **承認待ちの台帳に本人確認情報を後から登録しても承認待ちのまま** — 編集で書類種別・書類の画像を
     登録した場合や本人確認済み会員に紐付けた場合は、承認待ちを自動で解除するよう修正。
B37. **台帳一覧の検索で「%」「_」がワイルドカード扱い** — POS側（B16）と同様に文字として検索するよう修正。
B38. **年度の選択肢が暦年基準** — 1〜3月は前年が「今年度」になるよう、年度（4月始まり）で選択肢を作成。
B39. **ログイン時のパスワード変更後にメッセージが無い**、**レジ精算・会員詳細・POS画面がタブレット/スマホで
     横にはみ出す**（明細表があると画面幅を超えていた）、**重複アラートの比較表示がスマホで窮屈**等の細部を修正。
B40. **入力エラーの項目名が英語で表示されていた** — 「admin_email は必須項目です。」のような表示を
     「メールアドレス は必須項目です。」に修正（システム管理画面・ログイン・パスワード変更）。

### デザイン改善

D1. **システム管理画面（/admin/）を全面デザイン** — CSSが一切無く（フェーズ2のTODOのまま）、ブラウザ既定の

D4. **ヘッダーに事業者名（テナント名）と権限を表示**。メッセージ（緑・赤の帯）に閉じるボタンを追加。

### 追加した機能

F1. **パスワードの再設定・ロック解除（テナント管理者）** — 以前はパスワードを忘れた利用者を復旧する手段が
    無く、DBを直接操作するしかなかった。ユーザー編集画面で仮パスワードを設定でき（ロックも解除・次回ログイン時に
    本人のパスワードへの変更を求める）、ユーザー一覧には「ロック中」「PW変更待ち」の表示と「ロック解除」ボタンを
    追加。オーナーのパスワードは他の管理者からは再設定できない（乗っ取り防止）。操作は監査ログに記録。
F2. **システム管理画面の機能追加** — テナント詳細で利用者ごとのパスワード再設定・ロック解除（オーナーが
    パスワードを忘れた場合の復旧手段）、停止中テナントの「再開」ボタン、利用状況（利用者数・台帳件数・
    最終ログイン）の表示、操作結果のメッセージ表示、操作の監査ログ記録を追加。テナント削除は誤操作防止のため
    テナントコードの入力を必須にした。削除済みテナントの編集（中途半端な再有効化）は不可。
F3. **販売予定価格（売価）** — 台帳に任意の「販売予定価格」を追加（`ledgers.sale_price`）。POSレジで商品を
    カートに入れると単価に自動入力され（変更可）、在庫一覧にも価格を表示する。以前はPOSで毎回単価を手入力する
    必要があった。
F4. **ダッシュボードの拡充** — 本日のPOS売上（件数・点数・取消）、承認待ち台帳の件数（管理者）を表示。
    各カードから該当の一覧（今月分・今年度分）へ移動できる。
F5. **会員番号の自動採番** — 会員の新規登録で会員番号を空欄にすると M-0001 形式で自動採番する。
    登録・更新後は会員詳細を表示。会員詳細に職業・年齢・本人確認書類の種別を表示。
F6. **台帳の新規登録の初期値** — 取引年月日に今日、拠点に利用者の所属拠点を初期表示。入力エラーは画面上部に
    一覧で表示する（下の方の項目のエラーにも気付けるように）。
F7. ログイン画面に「パスワードを忘れた場合は管理者に再設定を依頼」の案内を追加。
